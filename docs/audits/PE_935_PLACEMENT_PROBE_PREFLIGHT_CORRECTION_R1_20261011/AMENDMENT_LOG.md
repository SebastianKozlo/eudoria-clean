## ROUND 1 — defects detected by the first POST test execution and fixed (within the single planned set + first fix round)
1. **peak-before-refusal accounting defect** (budget.test B5 FAIL): `trackPeak(found.length + 1)` ran before `tryRetain`, so a REFUSED candidate inflated `peakRetainedCandidates` (5 at a cap of 4). Fix: tryRetain first, then trackPeak. Failure case retained: B5 asserts peak <= cap.
2. **double-charged layout attempt after exhaustion** (budget.test B3 FAIL: 702 attempts at cap 700): after a mid-payload exhaustion, the next admitted payload's analyzeBlob call burned one more layout attempt before stopping. Fix: scanInput skips further analyzeBlob calls when a shared budget kind (LAYOUT_EVALUATIONS / RETAINED_CANDIDATES) is already exhausted and records an honest `BUDGET_EXHAUSTED` skip row for the admitted-but-unanalyzed payload.
3. **exclusion census not exported per entry** (budget.test B2/B3 FAIL: `dispositions` missing from SUMMARY exclusionCensus objects): the census summary dropped the per-entry disposition list the tests (and auditors) need. Fix: SUMMARY exclusionCensus now carries the full per-entry dispositions plus dispositionCounts/dispositionTotal/censusOk.
4. **B1 test fixture violated its own gate** (budget.test B1 FAIL): the 33-entry SYNTHETIC_INPUTS fixture used single-ID tables, which the default minDistinctId=2 gate legitimately excludes — the test asserted candidates>0 for a fixture that could not produce any. Fix: new `recordsTwoIdSmall()` fixture (two distinct IDs). The tool was NOT changed for this item — the expectation was wrong, not the code.
5. **O1 legal-boundary positive control was unsatisfiable** (correction_matrix.test O1 FAIL): the maxHeader=0 positive control ran against a 16-byte-header fixture, which maxHeader=0 can never find. Fix: new `records80Headerless()` fixture for the maxHeader=0 boundary; the original records80 positive control retained under maxHeader=64. Again an expectation fix, not a code change.
6. **weak self-satisfying assertion removed** (correction_matrix.test O5): `assert.equal(c.status ?? 'CANDIDATE_ONLY', 'CANDIDATE_ONLY')` could not fail. Replaced with a real check: the serialized candidate record must not contain any placement-claim string.

Fix: Budget now tracks `externalRetained` (rows held by main) and `tryRetain`/peak accounting include it, so the peak across ALL structures obeys the ceiling; row pushes are refused at the cap with an honest BUDGET_EXHAUSTED skip.
