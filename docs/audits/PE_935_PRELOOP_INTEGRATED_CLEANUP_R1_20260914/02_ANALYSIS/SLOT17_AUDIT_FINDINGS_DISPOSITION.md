## AUD-F4 (P3) — SLOT17 entropia_rtti_probe.py docstring "+4 shifted" optional header claim

**Claim (SLOT17 00_Control/entropia_rtti_probe.py docstring, verbatim):**
`NOTE: this binary's optional-header standard-fields region reads +4 shifted relative to the winnt.h IMAGE_OPTIONAL_HEADER32 layout (the verified project tool 90_Tools\PEFrida\core\modbase.py read_pe_header() uses the +28 convention for ImageBase and returns 0x00400000 for this exact file).`

**This run's own byte derivation** (own struct reads of the physical EXE after fail-closed
SHA256+SIZE assert; raw dump = 01_RAW/ENTROPIA_PE_OPTIONAL_HEADER_DUMP.txt):
- e_lfanew (u32 @ file 0x3C) = **0x120**
- PE signature @ e_lfanew = 50450000 ✓
- optional header start = e_lfanew + 0x18 = **0x138**
- optional header Magic = **0x10B** (PE32)
- dword @ opt+0x1C (ImageBase, standard IMAGE_OPTIONAL_HEADER32 offset 28) = **0x00400000**
- dword @ opt+0x20 (SectionAlignment) = **0x00001000**
- word @ opt+0x46 (DllCharacteristics) = **0x0000**

**Adjudication:** the standard winnt.h IMAGE_OPTIONAL_HEADER32 layout holds EXACTLY:
ImageBase is at OptionalHeader+0x1C (= +28 decimal — the very "+28 convention" the
docstring itself cites), and reading +0x1C yields 0x00400000 directly. There is NO "+4
shift". The docstring's claim is internally contradictory (it cites the standard +28
convention as if it were a deviation) and contradicted by the bytes.

**DISPOSITION: REJECTED_WITH_EVIDENCE** (the "+4 shifted" claim is factually wrong;
standard layout confirmed; every future adapted script must use the standard wording).
Erratum in 02_ANALYSIS/SLOT17_ERRATA.md §3. The historical commit 5290e79 is never
