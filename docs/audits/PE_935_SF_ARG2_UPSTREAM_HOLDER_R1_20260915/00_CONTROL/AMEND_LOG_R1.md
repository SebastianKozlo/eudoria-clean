# AMEND_LOG_R1.md — corrections during run PE_935_SF_ARG2_UPSTREAM_HOLDER_R1_20260915

All corrections were applied BEFORE the final raw artifacts were produced; every
raw in this package was generated by the final script versions (hashes in
SCRIPT_SHA256.csv). No completed phase's raw was amended in place; each raw was
regenerated deterministically by its (edited) generator.

## A1 — capstone x87-store access misreport (capability finding)

- Finding: capstone 5.0.7 (python, x86, detail mode) reports operand access of
  `fstp dword [eax+0x14]` as READ=0x1 — architecturally wrong (FSTP writes).
  Discovered by the capability probe added to probe_identity.py; without an
  override the G4 census would silently miss every x87 store to [reg+0x14].
- Correction: architectural override for x87 store mnemonics in
  s0_common.mem_write_ops (X87_STORE_MNEMONICS forced to WRITE before any
  access check). IDENTITY_VERIFICATION.txt regenerated with the capability
  matrix (8 test rows).

## A2 — capstone per-call setup cost; map engine redesign (capability finding)

- Finding: `Cs.disasm()` has ~25-35ms fixed per-call setup cost (measured:
  2397 functions in 90s with a per-function-call design; slice=1MB
  first-insn 24-36ms flat). Per-function decode loops are forbidden.
- Correction: build_text_map rewritten as a single-instruction-stream state
  machine (one iterator per region; padding-resync only at data islands).
  Result: full .text (1,928,649 insns, 105,492 functions) in ~20s.
  Phase B / Phase C / negctl map passes agree exactly
  (functions=105492, calls=140640, jmps=47776, insns=1928649) — dual
  independent derivations.

## A3 — slice engine corrections (before the six-site slices were finalized)

- `push reg` was mis-scored as a register WRITE in backward slices; corrected
  (push reads its operand; only `pop` defines).
- ESP-relative arg reads: added declared esp-entry param heuristic (linear
  delta tracking of prologue push/pop/sub/add esp; any call/ret/esp-rewrite
  before the read refuses the heuristic -> BOUND_EXHAUSTED honestly).
- Extracted slice_call_arg for call-site arg reconstruction; added
  budget["max_level"] to tighten the declared 4-level bound per use.

## A4 — Phase C(iv): held-parameter ABI correction (arg0 -> arg2)

- First pass sliced ctor call-site arg0. The full ctor decode (ret 0xC) proved
  the ctor takes THREE stack args and the HELD param is arg2 ([esp+0xC]).
  All six-site slices were re-run with arg_index=2; HOLDER14_WRITER_RAW.txt
  regenerated. The corrected slices are the load-bearing ones (all NULL).
- The correction and its evidence are recorded in HOLDER14_WRITER_RAW.txt
  [IV-0] ("CORRECTION vs first pass") and REPORT P1-1.

## A5 — Phase C(ii): criterion-(b) upgrade (census)

- First classification used enclosing-function criteria only (3 family rows,
  1895 NON_FAMILY with summary reasons). Upgraded to the contract's criterion
  (b) as an exhaustive per-row proof: family-vtable fingerprint on the base
  register + deep base-def slices (levels<=3) + this-cross (caller ECX
  slices) + constructor-class resolution incl. operator-new chains, over all
  1,895 non-criterion-a rows. Result unchanged: 0 additional family writers;
  every row now carries a base-def verdict. CENSUS raw regenerated (3 passes
  during development; final pass text matches method).

## A6 — Phase D channel-4 state machine fixes

  with in-stream state resets at terminals and calls. Final census: 1,438
  candidates (THUNK_CALLER_CENSUS regenerated by the final version).
